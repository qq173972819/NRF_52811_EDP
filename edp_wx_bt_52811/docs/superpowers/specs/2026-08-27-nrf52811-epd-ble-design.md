# nRF52811 四色墨水屏与微信小程序 BLE 传图设计

## 目标与范围

把 `stm32_nfc_lite-master` 中 1.54 英寸四色墨水屏的初始化、刷新和休眠
时序移植到 `edp_wx_bt_52811`，并把该工程从 nRF52832 QFAA 改为
nRF52811 QFAA。微信小程序 `wx_epaper_lite-master` 保留现有图片选择、裁剪、
旋转、绘制和四色抖动功能，把 NFC 传图替换为 BLE 传图。

最终固件只保留以下四项功能：

- BLE 连接与图像传输；
- 1.54d、200×200、四色墨水屏驱动；
- LED 接收状态和低电量提示；
- CR2032 电池电压采样。

原有 Beacon 扫描、MPU6500、BMP581、ESP32S3 I2C 转发、NVS 和相关设备树
节点、源码、测试及配置全部删除。固件不增加 OTA、图片持久化、配对或多屏型
支持。

## 工程和硬件基础

固件继续使用当前工程的 Zephyr/NCS 3.3.0 构建方式。自定义板改名为
`my_nrf52811`，SoC 使用 nRF52811 QFAA。应用直接从内部 Flash 启动，不保留
nRF52832 工程中超出 192 KB Flash 容量的 MCUboot 双槽分区。

固定引脚如下：

| 功能 | 引脚 | 配置 |
| --- | --- | --- |
| EPD MOSI | P0.08 | SPIM MOSI |
| EPD CLK | P0.07 | SPIM SCK |
| EPD CS | P0.06 | 低电平有效 GPIO CS |
| EPD DC | P0.05 | 低电平命令，高电平数据 |
| EPD RST | P0.04 | 低电平复位 |
| EPD BUSY | P0.03 | 低电平忙，高电平空闲 |
| LED | P0.11 | 高电平点亮 |
| ADC_BAT | P0.02/AIN0 | CR2032 经 100 kΩ/100 kΩ 分压 |
| 可选唤醒输入 | P0.21 | 内部上拉，低电平从 System OFF 唤醒 |

P0.05 到 P0.08 与当前 UART 配置冲突，因此禁用 UART 控制台，只保留必要的
RTT 日志。P0.02/P0.03 不再配置为 I2C。

## 总体架构

小程序把最终画布转换为固定 200×200、2bpp、10,000 字节图像，计算 CRC32
后通过一个自定义 GATT 服务顺序发送。nRF52811 不分配 10 KB 整图缓冲区；
它检查每包偏移，一边累计 CRC32，一边把数据写入墨水屏控制器 RAM。只有收到
完整数据且 CRC32 正确后，固件才执行屏幕刷新。

这种流式方案把大图缓冲从 nRF52811 的 24 KB RAM 移到墨水屏控制器，给
Zephyr BLE 栈、工作队列和线程栈保留空间。传输中断、偏移错误或校验失败时，
控制器 RAM 中的数据不会触发显示刷新。

固件模块边界如下：

- `app_ble_epd`：广播、连接、GATT 服务、通知和传输状态机；
- `epd_154d`：SPI、GPIO、初始化、连续写 RAM、刷新、BUSY 超时和休眠；
- `app_led`：接收快闪、低电提示和状态优先级；
- `app_battery`：SAADC 采样、电压换算、阈值和回差；
- `epd_protocol`：不依赖硬件的包解析、长度/偏移检查和 CRC32，供 ztest 测试。

## 墨水屏数据和驱动

屏幕固定为 200×200 像素，每像素 2 位，每 4 个像素从高位到低位打包成一个
字节，总长度固定为 10,000 字节。颜色编码为：

| 颜色 | 2 位编码 |
| --- | --- |
| 黑 | `00` |
| 白 | `01` |
| 黄 | `10` |
| 红 | `11` |

小程序现有 `canvas2bytes_2bpp()` 已产生上述控制器原生编码。固件在发出屏幕
RAM 写命令 `0x10` 后直接传入这些字节，不调用 STM32 示例的 `Color_get()`；
后者会再次换色，导致小程序数据的颜色错误。

屏幕操作顺序为：

1. START 包通过静态检查后复位并初始化屏幕；
2. 等待 BUSY 变高，发出 `0x10` RAM 写命令；
3. 回复 READY，小程序开始顺序发送 DATA；
4. 每个 DATA 包用一次或多次批量 SPI 写入，CS 可在包间释放；
5. END 的长度和 CRC32 校验通过后发出 `0x12` 刷新命令；
6. 回复 REFRESHING，等待 BUSY 变高；
7. 屏幕进入休眠，回复 REFRESH_DONE，LED 熄灭。

所有 BUSY 等待使用可修改的超时宏。超时、断连或协议错误会终止当前会话，
关闭屏幕电源并进入休眠，不永久阻塞 BLE 工作线程。

## BLE 广播与 GATT 服务

默认广播名称为可修改宏 `NRF52811-EPD`。只允许一个未配对连接。128 位服务
UUID 放在主广播包，完整设备名可放在扫描响应包。

固定 UUID 为：

| 项目 | UUID | 属性 |
| --- | --- | --- |
| EPD 服务 | `A4E10001-2D7F-4C2B-9A1D-52811E154D00` | Primary Service |
| RX | `A4E10002-2D7F-4C2B-9A1D-52811E154D00` | Write With Response |
| TX | `A4E10003-2D7F-4C2B-9A1D-52811E154D00` | Notify |

Android 连接后尝试把 MTU 设置为 247；iOS 使用系统协商的 MTU。小程序通过
可用 API 获取实际 MTU；无法取得时按 20 字节特征值长度回退。DATA 的最大
图像负载为 `ATT_MTU - 6`：ATT 写入开销 3 字节，应用命令和偏移共 3 字节。
小程序始终串行等待一次 Write With Response 成功后再写下一包。

## 应用层协议

协议版本为 `0x01`。所有多字节整数采用小端序。一次传图只能按
START → DATA → END 的顺序执行。

### 小程序写入 RX

START，固定 14 字节：

| 偏移 | 长度 | 字段 | 固定值或含义 |
| --- | --- | --- | --- |
| 0 | 1 | command | `0x01` |
| 1 | 1 | version | `0x01` |
| 2 | 2 | width | `200` |
| 4 | 2 | height | `200` |
| 6 | 1 | format | `0x01`，四色 2bpp |
| 7 | 1 | reserved | `0x00` |
| 8 | 2 | total_length | `10000` |
| 10 | 4 | crc32 | 10,000 字节图像的 CRC32 |

DATA，至少 4 字节：

| 偏移 | 长度 | 字段 | 含义 |
| --- | --- | --- | --- |
| 0 | 1 | command | `0x02` |
| 1 | 2 | image_offset | 本包首字节在图像中的偏移，范围 0–9999 |
| 3 | N | payload | 图像数据 |

DATA 没有单独的长度字段，长度由本次 GATT 写入值减 3 得到。固件只接受
`image_offset == expected_offset` 且不会越过 10,000 字节的包。

END，固定 7 字节：

| 偏移 | 长度 | 字段 | 含义 |
| --- | --- | --- | --- |
| 0 | 1 | command | `0x03` |
| 1 | 2 | total_length | `10000` |
| 3 | 4 | crc32 | 必须与 START 及固件累计值一致 |

### 固件通过 TX 通知

| 状态 | 数据 | 含义 |
| --- | --- | --- |
| READY | `81 01 00 00` | 协议版本 1，期望偏移 0，可发送 DATA |
| REFRESHING | `82` | 数据校验通过，屏幕正在刷新 |
| REFRESH_DONE | `83` | BUSY 已释放，屏幕已休眠，刷新完成 |
| ERROR | `E0 error expected_offset_le16` | 当前传输已终止 |

错误码固定为：

| 错误码 | 含义 |
| --- | --- |
| `0x01` | 状态顺序错误 |
| `0x02` | START 版本、尺寸、格式或字段错误 |
| `0x03` | DATA 偏移错误 |
| `0x04` | DATA 或 END 长度错误 |
| `0x05` | CRC32 错误 |
| `0x06` | EPD BUSY 超时 |
| `0x07` | EPD SPI/GPIO 操作失败 |
| `0x08` | 内部资源或初始化失败 |

每次 DATA 的 GATT 写响应只表示该包已被固件接收并处理；发送百分比按成功
写入的图像字节数计算。发生 ERROR 或断连后，小程序从 START 重新发送整图，
不做包级断点续传。

## LED 和电池状态

LED 为 P0.11 高电平点亮。状态优先级为：

1. BLE 图像传输或屏幕刷新：快速闪烁；
2. 空闲且电量低：每隔一段时间执行一次三短一长；
3. 正常空闲：熄灭。

接收期间低电提示暂停。收到 REFRESH_DONE、传输失败或连接断开后，LED 先
熄灭；若仍处于低电状态，等下一个告警周期再执行三短一长，不把两种模式混合。

默认可修改宏为：

```c
#define BATTERY_LOW_THRESHOLD_MV          2600
#define BATTERY_LOW_HYSTERESIS_MV          100
#define BATTERY_SAMPLE_INTERVAL_MS       60000
#define BATTERY_LOW_ALERT_INTERVAL_MS    60000
#define LED_RX_BLINK_INTERVAL_MS            80
#define LED_LOW_SHORT_ON_MS                100
#define LED_LOW_SHORT_OFF_MS               100
#define LED_LOW_LONG_ON_MS                  500
```

SAADC 使用 P0.02/AIN0、内部 0.6 V 参考、1/6 增益、12 位分辨率、足够长的
采集时间和多次采样平均。电池毫伏值按 ADC 引脚电压乘以 2 计算。低于
2600 mV 进入低电状态，只有回升到 2700 mV 及以上才退出，以避免临界点反复
触发。

100 kΩ/100 kΩ 分压从 3 V CR2032 持续消耗约 15 µA，这部分硬件静态电流在
System OFF 中仍然存在。当前 PCB 通过固件无法切断这条通路；后续 PCB 应考虑
GPIO/MOSFET 控制分压，或提高阻值并增加合适的 ADC 采样电容。

## 低功耗模式

使用编译期宏在“持续慢广播”和“限时广播后 System OFF”之间选择，默认使用
持续慢广播：

```c
#define POWER_MODE_SLOW_ADVERTISING  0
#define POWER_MODE_AUTO_SYSTEM_OFF   1

#ifndef APP_POWER_MODE
#define APP_POWER_MODE POWER_MODE_SLOW_ADVERTISING
#endif

#define BLE_SLOW_ADV_INTERVAL_MS       2000
#define BLE_ACTIVE_ADV_INTERVAL_MS      500
#define BLE_IDLE_DISCONNECT_MS        30000
#define BLE_AUTO_OFF_TIMEOUT_MS      300000

#define WAKEUP_GPIO_PIN                  21
#define WAKEUP_GPIO_ACTIVE_LEVEL           0
```

`POWER_MODE_SLOW_ADVERTISING` 的行为：

- 未连接时每 2 秒发起一次 BLE 广播事件，间隔可通过宏修改；
- 刷新完成后允许连接保留 30 秒，持续空闲后主动断开并恢复慢广播；
- 广播事件之间由 Zephyr 进入 System ON 空闲状态，不使用轮询或忙等待；
- 不自动进入 System OFF，手机可随时重新发现设备。

`POWER_MODE_AUTO_SYSTEM_OFF` 的行为：

- 上电后每 500 ms 发起一次广播事件，从上电开始计时 5 分钟；
- 5 分钟到期且设备空闲时停止广播和连接，停止 ADC 定时工作，关闭 LED 和
  SPI，确认屏幕已经休眠，然后进入无 RAM 保持的 System OFF；
- 到期时若正在接收图片或刷新屏幕，只设置待关机标志；必须等刷新结束、发出
  REFRESH_DONE 后再断开连接并进入 System OFF，不中断有效传输；
- P0.21 配置为内部上拉和低电平 SENSE。PCB 引出的 P0.21 瞬间接地后从
  System OFF 唤醒，唤醒表现为一次完整重启；P0.21 不是硬件 RESET 引脚；
- 进入 System OFF 前必须确认 P0.21 为高电平。若引脚已为低电平，暂缓关机，
  防止立即唤醒形成循环；
- System OFF 期间不执行 ADC 采样和低电 LED 提示。

两种模式都在刷新后让墨水屏进入深度休眠，在 ADC、SPI 和 LED 不工作时释放
或配置为低泄漏状态。功耗验收必须测量整板电流，不能只引用芯片数据手册数值。

## 微信小程序交互

首页保留原有视觉样式、图像模式、方向、四色抖动算法、阈值、画笔、颜色、
清空、撤销、重做、裁剪和画布。屏幕型号固定为 `1.54d / 200×200 / 四色`，
删除型号选择器和其他型号配置。NFC 页面、NFC 适配器调用和 NFC 权限全部删除。

界面只增加或替换以下元素：

- 导航栏下方增加连接按钮；未连接显示“连接蓝牙设备”，已连接显示设备名和
  已连接状态；
- 点击连接按钮打开附近设备列表，按 RSSI 从强到弱排序；列表优先显示
  `NRF52811-EPD`，但允许用户点击实际发现的匹配服务设备；
- 选择设备后停止扫描，建立连接，发现固定服务/特征值并订阅 TX 通知；只有
  这些步骤全部成功才显示已连接；
- 页面底部原 NFC 悬浮按钮改为“发送”按钮并使用现有页面风格；
- 页面卸载时停止扫描、注销监听并关闭 BLE 连接和适配器。

点击发送时：

1. 未连接时提示先连接；没有可发送画布时提示先选择或绘制图片；
2. 调用现有四色抖动和 `canvas2bytes_2bpp()` 得到固定 10,000 字节数据；
3. 计算 CRC32，发送 START 并等待 READY；
4. 按实际 MTU 串行发送 DATA，弹窗显示“数据发送 xx%”；
5. 发送 END，收到 REFRESHING 后弹窗改为“墨水屏刷新中”；
6. 收到 REFRESH_DONE 后关闭进度态并提示“刷新完成”。

进度层在传输和刷新期间不能因点击遮罩而误关闭。蓝牙未开启、权限失败、扫描
失败、连接断开、服务不匹配、写入失败、ERROR 通知和刷新超时均显示明确错误，
清理发送状态并允许用户重新连接或重发。

BLE API 与协议编码从页面逻辑中分离：连接管理负责微信 BLE 生命周期，纯协议
模块负责 CRC32、START/DATA/END 编码和通知解析。纯协议模块不引用 `wx`，可由
Node 测试直接加载。

## 测试与验收

实施遵循测试先行。固件先用 Zephyr ztest 覆盖：

- 正确 START 进入接收状态并把期望偏移置 0；
- 错误版本、尺寸、格式和总长度被拒绝；
- 连续 DATA 推进期望偏移，重复、跳包、空负载和越界被拒绝；
- 正确 END 触发刷新，长度或 CRC32 错误不刷新；
- 断连和 BUSY 超时终止会话；
- 2600/2700 mV 阈值回差；
- 接收快闪覆盖低电提示，结束后回到正确空闲状态。
- 慢广播模式不会触发自动关机；
- 自动关机模式在空闲超时后执行关机，在传输或刷新中只设置待关机标志；
- P0.21 已为低电平时拒绝进入 System OFF，拉高后才能关机。

小程序用 Node 内置测试运行器覆盖：

- 已知向量的 CRC32；
- START 和 END 的精确字节序；
- 不同 MTU 下 DATA 分包的偏移、大小、连续性和总长度；
- READY、REFRESHING、REFRESH_DONE 和 ERROR 解析；
- 2bpp 输出长度和四色编码样例。

自动化验收还包括 nRF52811 板目标完整编译、Zephyr RAM/Flash 占用检查和小程序
静态检查。真机验收包括：

- Android 和 iOS 扫描、连接、通知订阅及 MTU 回退；
- 黑、白、黄、红四色测试图的颜色、方向和完整性；
- 发送百分比、刷新等待和 REFRESH_DONE 完成提示；
- 中途断线、错误偏移、错误 CRC 和 BUSY 超时均不刷新残图；
- 接收期间 LED 快闪，完成后熄灭；
- 模拟低电压时按周期三短一长，传输时低电提示被覆盖。
- 分别编译并验证两种 `APP_POWER_MODE`；
- 慢广播模式验证 2 秒广播间隔和 30 秒空闲断连；
- 自动关机模式验证 5 分钟超时、传输完成后延迟关机和 P0.21 接地唤醒；
- 使用电流表分别测量慢广播、连接空闲、System OFF 和屏幕刷新阶段的整板电流。

没有连接实际 nRF52811 PCB 和墨水屏时，自动化测试与编译不能替代最后的真机
颜色、BUSY 极性、电池测量误差和功耗验证；交付时需明确区分已自动验证与待硬件
验证项目。
